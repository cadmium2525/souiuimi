# 言葉と、その場の事情から考える出題

2026-10-15。通常プレイは5舞台で出題を生成します。CASE 01〜03・05はA/B/C、CASE 04は2択のA/Bです。今回の改修では、部屋・契約・封筒・担当者などの英数字コードを照合する仕組みと、駅前の時計換算を撤去しました。

## 今回の設計方針

プレイヤーが考えるのは「誰が、何のために、この言葉を使ったか」です。その部屋の次の使い方、相手との会話、本人の過去の言い方、作業の相手や目的を手がかりにします。ランダムなコードを覚えて別表の行を探すことや、他案件・前日の同じ番号を除外することを、判断の条件にしません。

各回の記録は、一つの仕事についての自然な文書と会話です。名前、資料名、日時、金額、人数などは、場面に必要な情報として表示します。ケースの変化は、今回の仕事の目的や発言の文脈を変えることで作ります。正解を示すコードに自然な名称を付け替えただけの表引きにはしません。

調査カードとノートには、書面の原文や見えた物の状態を表示します。主人公の感想や先回りの解釈を付け足しません。未発見の場所マーカーや記録名も表示しません。決まった枚数の記録を集めることは回答の条件にせず、必要だと思う情報から判断できます。結果後の振り返りでは、その結末を裏づける文脈を説明します。

## CASE 01「適当に片付けといて」

同じ仮設オフィスで、明日の用途を変えます。

- A：来客との打ち合わせに今の机と椅子を使う。来客準備の付箋もあるため、掃除して迎える準備をする。
- B：建物をその場で使い続ける一方、室内を空にする予定があり、借りた机と椅子の返却日でもある。家具と備品を運び出す。
- C：建物のある土地まで通路に変わり、仕事場所は別の現場へ移る。上司はいつもの席順と机上の配置を残したい。この会社の移動式オフィスを建物ごと移設する。

予定表、管理人からの連絡、上司の付箋で、一つの仕事の事情を読み取ります。部屋番号や契約番号は登場しません。クレーン、コンテナ、会社紹介はどの回にも存在し、設備の有無だけで今回の依頼を決めません。Cは会社の設定に根拠を置いた漫画的な展開です。

Bの演出は片付けの終盤から始め、残りの荷物をゆっくり運びます。全量の搬出を短時間に早送りして見せません。

## CASE 02「T時10分前集合」

時計IDと時差換算を撤去し、駅前と会場の時計は同じ時刻に合わせます。「T時の10分前」「T時10分の5分前」「T時10分のすぐ前」という受け取り方のうち、今回この上司が意図した時刻を考えます。

前回のチャットと部長の手帳には、同じ人が以前使った「○時10分前」と、そのとき実際に合流した時刻が記録されています。時刻を変えた2件のやりとりから、その人の言い方を読み取ります。「少し前」が常に5分や1分を意味すると一般化したり、ある受け取り方を「普通の意味」と呼んだりはしません。

選択肢は3通りの時刻です。上司の過去の使い方を変えることで、A/B/Cのいずれも今回の意図になります。バスの時刻と天気は場面の事実ですが、発車の何分前か、雨の何分前かだけを固定の正解規則にはしません。

意図した集合時刻なら上司と合流して共同乗車し、早ければ待ちぼうけです。遅れても便に間に合えば上司を待たせて乗車し、間に合わなければ乗り遅れます。指定時刻に合うことと、単にバスに乗れることを区別します。バスは走り去って画面から消えます。

## CASE 03「お釣りはいいよ」

買い出しの依頼は一件だけです。何のお金で買ったのか、残金についてどんな約束をしていたのかを、封筒の自然な名札と会話、買い物の記録から読み取ります。

- A：会社の買い出し用のお金。上司個人へ返す必要はなく、残額を会社経理へ返す。
- B：上司が私費で頼んだ買い出し。残額を担当者へのお礼にする約束があるため、自分が受け取る。
- C：参加者で出し合ったお金。残額を募金に回すことに全員が同意しているため、店の募金箱へ入れる。

封筒番号から資金コードを引く台帳や、別の封筒の処理条件は使いません。募金箱にコードは付けません。募金箱があるだけで寄付を正当化せず、今回のお金についての合意を根拠にします。会社のお金の扱いは作中の設定です。

支払額・購入額・釣銭は同じ出題データを参照します。主人公が残金を経理窓口、自分の財布、募金箱へ運ぶ3行動はいずれも10秒です。

## CASE 04「1万円弱でお願い」

依頼する相手は部長で固定し、今回の催事の用途を自然に示します。部長が以前「○円弱」と言ったときの実額を、本人との過去のやりとりから読みます。再出題では用途と過去のやりとり、現在の候補額が変わります。別の依頼番号から担当者番号をたどる作業はありません。他の担当者の記録や、同じ番号の前日割当ても混ぜません。

Aは1万円未満、Bは1万円を少し超える封筒の2択です。金額につく「弱」の辞書上の意味は少し少ないことです。Bが意図される回は話者の取り違えを扱い、結果で上司自身が認めます。この回にAを選んで不足しても、日本語の解釈は合っていると明言します。語義と個人の誤用を区別する方針・出典は [amount-language-notes.md](amount-language-notes.md) に記録しています。

下側9,300〜9,900円、上側10,100〜10,700円の候補から一通を選びます。「弱」が特定の円数を定義するとは扱いません。2行動は各10秒で、意図どおりの受け取り、不足、差額を返す結果に分かれます。

## CASE 05「資料、まとめといて」

指示は「この資料、まとめといて。午後渡せるようにね」。資料の自然な名前を表示し、その資料を使う目的と相手の話を読みます。

- A：説明時間は3分。参加者にはすでに全文を配布していて、説明担当者の手元メモがまだない。要点を1枚に整理する。
- B：各自がページを行き来して読み比べる会で、スクリーンも配布済みの紙もない。人数分の資料セットを作る。
- C：原本の閲覧場所を保管室へ移し、保管担当者が現物を引き取る。原本を全量集めて搬出する。

上司のチャット、午後の予定、当日の案内、資料そのもの、受取相手の伝言、原本の保管メモ、共用備品の7か所を調べられます。どれも今回の一件に関する記録です。資料・行先・受付の番号、対応表、前日の別の行先はありません。資料名、人数、ページ数は正解と独立に変わります。

A10秒・B12秒・C14秒。Cは最後の数束を足し、巨大クリップで留めて台車でゆっくり運びます。巨大な束は集約作業の漫画的な誇張で、特定の梱包形状を推理する問題ではありません。詳しくは [document-case-notes.md](document-case-notes.md) を参照してください。

## 生成・再挑戦・検証

`createCase(stageId, seed)` は整合した場面の事実を作り、純粋なsolverで正解を求め、作者の文章テンプレートへ反映します。各solverが読むのは仕事の目的、相手、資金の出所と合意、同じ人の過去の言い方などです。演出用の正解欄から答えを逆算しません。外部AI・API・サーバーは使いません。

`validateCase` と各ケースのvalidatorは、事実同士の矛盾、唯一解、調査本文・台詞・選択肢・3D表示用データの一致を確認します。成功した `CaseInstance` は内部まで凍結し、探索中に変更しません。コードや日時の表引きがプレイヤー向けの文に戻らないことも検証します。

「同じ依頼をやり直す」は同じ出題と事実を保持し、時間・証拠・位置・選択を戻します。「次の依頼を受ける」は全5舞台から新しい出題を生成します。タイトルからの開始も新規出題です。正解をA/B/Cの順番で循環させません。

5舞台に3+3+3+2+3、計14の正解系統があります。名前・金額・人数などを変えるだけではなく、仕事の目的や話者の文脈を変えます。各舞台3,000seedを含む単体テストで、自然な文脈からの判断、本文の一致、矛盾拒否、凍結などを確認します。ブラウザでの実行結果と未確認項目は [acceptance.md](acceptance.md) に記録します。

## 変更の経緯と今後

v6でオフィスと駅前のランダム出題、v7で金銭のCASE 03、v8で「1万円弱」のCASE 04、v9で資料のCASE 05を追加しました。旧実装は、番号と日付の対応表や時計のずれを変えて出題していました。ユーザーから「言葉の真意を判断するゲームなのに、謎のローマ字に頭を使うのは違う」と指摘を受け、今回の自然な文脈による出題へ改めました。過去版の検証報告は [acceptance.md](acceptance.md) に履歴として残しています。添付された原企画の保存版 `devpack/` は変更しません。

現在は、調査物の位置と、各ケースの大きな意味の分岐は固定です。何度も遊べば型を覚えられます。今後のケース追加、自然な会話のバリエーション、予定変更、根拠も答える遊びは未実装です。覚えて役立つのは番号照合の手順ではなく、その場の目的や相手の言い方に目を向けることです。過去の言い方から今回の意図を予測する設定は、現実の会話の意図を確実に保証するという主張ではありません。
