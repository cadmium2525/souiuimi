# 複数の手がかりから、言葉の真意を考える出題

2026-10-16。通常プレイは5舞台で出題を生成します。CASE 01〜03・05はA/B/C、CASE 04はA/Bです。番号照合と時計の時差換算を撤去した構成に、今回は「同じ1枚の文面が、異なる正解の場面にも出る」という設計条件を加えました。CASE 03は、店舗から社内休憩室へ舞台を改めています。

## 設計条件

プレイヤーが考えるのは「この状況で、上司は何を頼んだのか」です。手がかりを難しい言葉にしたり、答えの文を途中で切ったりする代わりに、用途と承認、予定と移動、用件と資金など、別々の事実を読んで判断する構成にします。

各調査カードの全文を、名前や日付などをそろえた全状況で比較します。同じ文面に複数の正解が対応し、1枚だけでは答えが決まらないことを検証します。そのうえで、必要な記録を組み合わせたときには一意の答えが得られるようにします。物体の有無、標識、資料名や金額だけが回答を知らせる構成も避けます。

各記録は、その場所にある理由を持たせます。自分のスマホは自分の持ち物、持ち帰ったレシートは会社の机、社内チャットは共有PCで調べます。店舗に会社の経理資料を置く設定にはしません。複数の用件を扱う場合も「ノート」「筆記具」のような自然な用件名を使い、別表の番号をたどらせません。

同じ文面が複数の正解に出ても、「この資金なら余りは募金へ」という条件付きの指示を書けば答え表になってしまいます。単独カードの曖昧性に加え、調査文が回答後の行動を直接指示していないかを確認します。

調査カードとノートには、書面の原文や見えた状態だけを表示します。主人公の感想や先回りの解釈、未発見の場所マーカーや記録名は追加しません。決まった枚数の記録を集めることは回答の条件にしません。結果解説は意味と短い根拠の2文に絞り、記録の全文は折りたたみから確認できます。

## CASE 01「適当に片付けといて」

二人から届いた明日の利用相談を、手がかり02で読みます。相談には、今の机での打ち合わせ、床の端まで確認する点検、新しい現場で今の配置を使う仕事のうち二つがあります。手がかり04には、部長がどちらの人の相談を引き受けたかだけを記します。

相談だけではどちらが採用されたかわからず、承認の返信だけではその人の相談内容がわかりません。両方を読んで、Aの掃除、Bの家具搬出、Cの建物ごとの移設を判断します。承認された人の名前も、相談が表示される位置も、固定の答えにはしません。

クレーン、コンテナ、会社紹介は毎回存在します。Cは、この会社の移動式オフィスという設定に根拠を置く漫画的な展開です。Bの演出は片付けの終盤から始め、残りの荷物を落ち着いた速さで運びます。

## CASE 02「T時10分前集合」

手がかり02は、部長が公民館前を何時に出る路線バスで来るかというメッセージです。手がかり04は、公民館前から駅前までの路線案内です。出発時刻と所要時間を合わせると、その回の集合時刻がわかります。

6通りの状況を用意し、同じ出発時刻にも、同じ所要時間にも、二つの集合解釈が対応します。片方だけを見ても回答は決まりません。バスの時刻も、それだけで正解が一つに絞られない時刻から生成します。時計はすべて同じ時刻で、時計IDや時差換算はありません。

選択肢は「T時の10分前」「T時10分の5分前」「T時10分のすぐ前」に当たる3時刻です。特定の解釈を一般に正しい・普通とは断定せず、今回の部長の意図との一致を扱います。「少し前」が常に5分や1分を意味するという主張もしません。

演出は、時間どおりの合流、早着、遅刻して乗車、乗り遅れに分かれます。バスは走り去り、画面から消えます。

## CASE 03「お釣りはいいよ」

舞台は、買い出しから戻った社内休憩室です。ノートと筆記具の二つを頼まれており、そのうち一件を済ませています。

封筒と持ち帰ったレシートで、どちらを済ませたかを確かめます。出発前のチャットには、二つの用件それぞれについて、会社の仮払い・上司の財布・本棚づくり係からの預かり金のどれかを記します。募金箱には、文具購入用の現金を本棚づくり係へ手渡した出納控えがあります。自分のスマホは納品の連絡だけです。

同じ二用件への資金説明でも、済ませた用件が違えば結末が変わります。同じ買い物名でも、資金の出所が違えば結末が変わります。異なる出所の組合せと、済ませた用件を合わせた12状況から生成します。Aは会社での精算、Bは上司の私費に対する今回の発言を受取の許可と読む行動、Cは募金から預かった残金を元の箱へ戻す行動です。

社内の募金箱と出納控えは、どの回にも存在します。それが見えるだけでCには決まりません。調査文に残金の行き先を指示する台詞は置かず、資金の持ち主と今回の発言を根拠にします。3行動はいずれも10秒です。

## CASE 04「1万円弱でお願い」

手がかり02には、部長の過去の依頼文があり、「弱」または「強」を使います。手がかり03には、その依頼で受け取り、本人が確認した額があります。

過去の語が弱/強、受取額が基準より下/上という4状況を扱います。たとえば同じ少し多い受取額でも、元の依頼が「強」なら辞書どおり、「弱」なら取り違えです。受取額だけでも、依頼文だけでも今回のA/Bは決まらず、二つを合わせて本人の使い方を予測します。

今回の選択肢は、Aの1万円未満とBの少し超える額です。「弱」の辞書語義は両結果で変えません。Bの回では部長が取り違えを認め、Aを選んで不足しても日本語の解釈は合っていると明言します。具体的な円数は用意された2通の封筒から選び、「弱」が特定の額を定義するとは扱いません。詳細と出典は [amount-language-notes.md](amount-language-notes.md) を参照してください。

## CASE 05「資料、まとめといて」

会議の前後、全文の配布状況、検討記録の所在の3項目を、独立した8状況で扱います。手がかり02は検討会の時刻、03は全文の送付記録、06は担当者の指摘が原本と別紙のどちらに残るかです。

会の前で全文が未配布ならBの参加者分のセット、配布済みならAの説明用の要点です。会の後で検討記録が原本にだけ残るならCの原本一括受渡し、別紙の議事メモがあるならAの報告用の要点です。

書き込みのある原本は、会の前のA/Bにも登場します。配布済みの記録もA/Cに登場します。「原本を保管室へ」と書いて答えを直接伝えるカードは使いません。資料名、人数、ページ数、共用備品、調査位置と標識も、正解を知らせるためには変えません。

演出はA10秒・B12秒・C14秒です。Cは最後の数束を足し、巨大クリップで留め、台車でゆっくり運びます。巨大な束は漫画的な誇張で、特定の梱包形状を推理する問題ではありません。詳細は [document-case-notes.md](document-case-notes.md) を参照してください。

## 生成・再挑戦・検証

`createCase(stageId, seed)` は場面の事実を作り、純粋なsolverで正解を求め、作者の文章テンプレートへ反映します。演出用の正解欄から答えを逆算せず、外部AI・API・サーバーは使いません。

各validatorは唯一解、記録の整合性、台詞・選択肢・描画用データとの一致を確認します。単体テストは全状況の実際のカード本文を比較し、単独で答えが決まらないことと、複数の記録で答えが決まることを確認します。各舞台3,000seed、計15,000出題の検証も行います。成功した出題は内部まで凍結して保持します。

通常プレイは「ゲームスタート」で5舞台の順番を一度だけシャッフルし、残った舞台から順に依頼を生成します。同じ舞台は1周に一度だけ登場します。最初の回答と調査数・探索時間を記録し、5件を終えるとリザルトで振り返ります。次のケース順と、正解を生成する乱数は分離しています。タイトルへ戻ると途中の成績を終了し、再スタートは新しい5件になります。

単独のケース選択・同じ依頼のやり直しは診断モードに残します。A/B/Cの順番で正解を循環させません。5舞台で3+3+3+2+3、計14の正解系統です。ブラウザの検証結果は [acceptance.md](acceptance.md) に記録します。

調査物の位置と大きな意味の分岐は固定で、繰り返せば型を覚えられます。今回の改修は、その型を覚えても1枚だけで回答できる状態を避けるものです。ケース追加、根拠も答える遊び、作者のルール外の自由生成は未実装です。初期企画の保存版 `devpack/` と過去の受入記録は履歴として維持します。
