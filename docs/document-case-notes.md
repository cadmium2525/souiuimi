# CASE 05「資料、まとめといて」

2026-10-15。v9で追加し、今回の改修で資料・行先・受付番号の照合を撤去しました。現在は、一件の仕事の目的と受取相手の話から「まとめる」の意味を判断します。

## 判断の対象

- A：内容の要点を1枚に整理する。
- B：ページ順をそろえ、人数分の配布セットを作る。
- C：原本を全量集めて搬出する。

上司の指示は「この研修資料、まとめといて。午後渡せるようにね」のように、資料の自然な名前で伝えます。資料名は全3通りの文脈で使われ、名前自体は答えを示しません。

Aの回は、午後の説明が3分で、参加者は全文をすでに持っています。まだないのは説明担当者の手元メモです。全文を複製し直したり現物を運び出したりするより、短い時間で伝える準備としての要点整理が合います。

Bの回は、参加者が各自の手元でページを見比べる読み合わせです。スクリーンはなく、紙の資料もまだ配っていません。各人が別のページを見られるように、全文を人数分そろえます。

Cの回は、今後の原本閲覧場所を保管室へ移します。保管担当者は現物を引き取り、準備室の棚には原本を残しません。要約や複製の作成では、この仕事を終えられません。

`DocumentCaseFacts` は用途、相手、原本の扱いを持ちます。`solveDocumentFacts` は3点が一致する組合せだけを受け入れます。説明会なのに受取相手が保管担当、読み合わせなのに原本をすべて移転、といった矛盾した出題を拒否します。演出用の `intendedChoice` は判断根拠にしません。

## 調査と再出題

調べる対象は、上司のチャット、午後の予定、当日の案内、机の資料、受取相手の伝言、原本の保管メモ、共用備品です。一件の仕事に関する自然な記録だけを置きます。他案件や前日の同じ番号で混乱させません。内部の `C01` などはプログラムが物を識別するための名前で、照合すべき情報として表示しません。

資料名、日付、ページ数、人数は正解と独立に変わります。共用備品はどの回も同じです。紙の束や大型クリップがあることだけでCとは決められません。

調査カードとノートには、文書の原文や物の状態だけを表示します。主人公の感想、解釈、先行する場所マーカー、未発見の記録名は追加しません。結果の振り返りでは、午後の予定、当日の案内、原本の保管メモから用途の違いを説明します。

## 演出

Aは原稿を確認して1枚を仕上げ、Bは配布セットをそろえます。Cは大部分を積み終えた状態から最後の数束を足し、巨大クリップで留めて台車で短距離運びます。固定カメラで見せ、短時間に全量を往復搬出する早送りは使いません。

Cで判断するのは「現物を全量集めて運ぶ」という仕事です。主人公より高い紙のタワーと巨大なクリップは漫画的な誇張です。作業相手が裸の巨大束や特定の梱包形状を要求する設定ではありません。正解時は上司が当然のように受け取り、取り違えた回は用途と成果物のずれを指摘します。

手がかりは7つ、探索120秒、A10秒・B12秒・C14秒。3通りすべてが当日の意図になり、全9組合せに結果があります。再挑戦は同じ出題を保持し、次の依頼は全5ケースから新しい出題を生成します。

専用単体テストは3,000seedの一貫性、名前・日付・量による固定正解がないこと、矛盾と表示改変の拒否、凍結、固定台本からのコード除去を確認します。ブラウザの検証結果と実機での未確認事項は [acceptance.md](acceptance.md) に記録します。
